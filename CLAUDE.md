# Help Desk Badge Generator

## Project Overview

**Stack:** Bun + Hono + SQLite (WAL mode) + Playwright (server-side badge rendering) + Sharp (image processing)
**Production:** `badge.helpdesk.band`
**Domain:** `helpdesk.band` — badge app at `badge.`, game at `game.`, root reserved for band site

**Entry Points:**
- `src/server.ts` — Entry point: reads the environment, prepares `./data` and the DB, wires the services into the app, pre-renders print assets
- `src/app.ts` — `createApp(deps)`: the Hono app (security headers, body cap, admin gate and lockout, routes, static files, 404). Starts nothing, so tests build the same app
- `src/render-pool.ts` — Playwright browser and warm page for badge renders
- `src/live-stream.ts` — SSE clients, connection caps, broadcasts
- `src/client-ip.ts` — the client-IP and trusted-proxy rule
- `src/badge-files.ts` — the files stored per badge, removal and the orphan sweep
- `src/http.ts` — `fail()`, the one error-response shape
- `src/db.ts` — SQLite persistence layer (schema, migrations, CRUD)
- `src/routes/public.ts` — Badge creation, retrieval, org chart API + CORS for game.helpdesk.band
- `src/routes/admin.ts` — HR dashboard, analytics, demo/presentation modes

**Ports:**
- Development: `3000` (default)
- Production (Docker): `3030`
- Tests: `3333` (E2E only)

**Cross-origin:** `/api/badge/:id` has CORS for `https://game.helpdesk.band` (Hostile Takeover card game). `/game` redirects 301 to `https://game.helpdesk.band`.

**Data Layout:**
- `data/badges.db` — SQLite database (WAL mode)
- `data/photos/` — Source JPEGs (`{employee_id}.jpg`)
- `data/badges/` — Rendered badge PNGs (`{id}.png`, `{id}-nophoto.png`)
- `data/thumbs/` — 320px thumbnails
- `data/headshots/` — 200px headshot crops

**Employee ID Format:** `HD-XXXXX` (5-digit random, collision-checked)

## Security Rules

1. **No innerHTML with user data.** All user-supplied content (name, title, department, song) must use `esc()` (from shared.js) or `textContent` / DOM API. Static HTML templates are acceptable. Full innerHTML audit completed (`c4dc73c`) — 55 usages classified.
2. **Admin routes live in `src/routes/admin.ts`** — all admin endpoints use `/api/admin/*` prefix with Bearer token auth middleware.
3. **Tokens are hashed.** Delete tokens stored in DB via `hashToken()` (SHA-256). Raw tokens returned to user once, never stored.
4. **Validate uploads with Sharp.** All image uploads must pass `sharp(buffer).metadata()` before saving. Only `image/*` MIME types accepted.
5. **Generic error messages only.** Never leak internal state, file paths, or stack traces in API responses. Use themed messages ("Badge printer is overheating").
6. **Field clamping.** All user text fields capped at 200 characters via `clampField()`.
7. **Rate limiting enforced.** Badge creation: 10/hour, 20/day (normal); 300/hour, 800/day (show mode). Admin auth: 5 failures → 15 min lockout.
8. **Print-ready badge export is admin-only.** `/api/admin/badge/:id/print` requires Bearer token. Moved from public routes — print formatting is a paid feature.

---

## Data Rules

1. **Multi-step writes in `db.transaction()`.** Any operation touching multiple rows or tables must be wrapped in a transaction.
2. **New statements go in the `stmts` object.** All prepared statements are cached at init time in `src/db.ts`. Never use ad-hoc `db.prepare()` in request handlers.
3. **Schema changes via `runMigration()`.** New columns/tables get a versioned migration (increment from current max). Migrations must be idempotent (check before alter).
4. **Employee IDs use `HD-XXXXX` format.** 5-digit numeric, generated by `generateEmployeeId()` with collision retry.
5. **Band members are HD-00001 through HD-00005.** Seeded on fresh DB, never regenerated.

---

## Code Quality Rules

1. **Frontend globals under `window.HD.state`.** No loose global variables. View state belongs in view modules.
2. **Cleanup in view `destroy()`.** Every view module must clean up timers, event listeners, D3 selections, and animation frames in its destroy function.
3. **No synchronous I/O in request handlers.** Use async `Bun.file()` / `Bun.write()` instead of `readFileSync` / `writeFileSync`. Exception: `existsSync()` for quick path checks.
4. **SSE client cap at 500.** `MAX_SSE_CLIENTS` in server.ts. Client-side exponential backoff (1s→30s) in live-viz.js and presentation.js prevents reconnect floods during server restarts.
5. **Profanity filter is two-tier.** Hard block (hate speech → 400) vs soft flag (edgy → created but flagged). General profanity is allowed — it's a punk show.

## Security Checklist for New Features

Before committing any new feature, verify:

- [ ] No `innerHTML` with user-supplied or server-fetched data (use `textContent`)
- [ ] All admin-only endpoints behind `/api/admin/*` prefix (Bearer auth applies automatically)
- [ ] Multi-step DB writes wrapped in `db.transaction()`
- [ ] No synchronous file I/O (`readFileSync`, `writeFileSync`) in route handlers
- [ ] Rate limiting applied to any new public endpoint that creates/modifies data
- [ ] Error responses use generic messages, no internal details leaked
- [ ] User text inputs clamped via `clampField()` (200 char max)
- [ ] Profanity filter applied to any user-visible text fields (name, title)
- [ ] Image uploads validated via `sharp().metadata()` before saving
- [ ] New DB columns added via `runMigration()` with version increment

## Lint Checks

```bash

grep -rn 'readFileSync\|writeFileSync' src/routes/ --include='*.ts'
```

## Testing

```bash
bun run test          # API + DB tests (never bare `bun test`: it picks up Playwright specs)
bun run test:api      # API integration tests only
bun run test:db       # DB unit tests only
bun run test:e2e      # Playwright E2E tests (starts its own server on 3333)
bun run lint          # Grep-based lint checks
bun run typecheck     # tsc --noEmit; CI runs it
bun scripts/transpile-fingerprint.ts   # hash of each file's transpiled code, for proving a comments-only change
bun run scripts/fight-sim.ts [count]  # Arcade fight Monte Carlo simulator (default 10k)
bun run scripts/rack-sim.ts [count]   # Rack packet stress test (default: 50/100/200/500)
```

**File naming convention:** `.test.ts` = Bun test runner, `.pw.ts` = Playwright runner. This prevents `bun test` from auto-discovering Playwright specs (which require the Playwright runner context).

Test harness uses temp SQLite DBs and mocked Playwright — no browser needed for API/DB tests.

- `tests/helpers/setup.ts` builds the real app with `createApp()` on a temp DB, with the renderer and live stream stubbed; `createTestApp(overrides)` replaces any service (e.g. a failing renderer). Requests come from a loopback peer with proxy trust on, so `X-Forwarded-For` sets a test's client address.
- `tests/helpers/spawn-real-server.ts` starts `tests/helpers/real-server.ts`, which boots the real `src/server.ts` in a child process for the SSE path and the full startup. The request header `x-test-peer` sets the socket address.
- `tests/api/real-server-snapshot.test.ts` records the real server's responses and security headers.
- `tests/api/api-snapshot.test.ts` records every read route and the badge lifecycle. An intended response change is accepted with `bun test tests/api/api-snapshot.test.ts --update-snapshots`.
- `tests/api/readme-routes.test.ts` fails when a route is missing from, or stale in, the README.
